##### 3 правила технологии
1. нет данныз длит. испытаний - вы не знаете технологию
2. нет интеграции и владельца - не будет внедрения
3. Если не бьется экономика - это тоже результат, просто другой маршрут

### Публичные выступления
- в выступлении важно не сам спич, а **изменения** у слушателей

- спич должен быть

	- полезным
		- какая аудитория?
		- какая цель у нас и аудитории?
		- мотивация аудитории

```mermaid
graph TD
    %% Входные данные
    subgraph Input ["1. Входные данные"]
        A1[Директория с CIF-файлами] --> B
        A2[config/thresholds.yaml] -.-> B
        A3[train_reference.csv] -.-> B
    end

    %% Процесс валидации
    subgraph Pipeline ["2. Ядро валидации (MVPipeline)"]
        B{Парсинг CIF} -- Ошибка --> R1[cif_parse_error]
        B -- Успех --> C{Геометрия}
        
        C -- d_min < 0.7Å --> R2[overlap]
        C -- V/atom вне нормы --> R3[volume_out_of_range]
        C -- d_min < 1.2Å --> S[Флаг: suspicious]
        
        C -- Норма --> D{Физика и Химия}
        D -- Плотность вне нормы --> R4[density_out_of_range]
        D -- Заряд ≠ 0 --> R5[charge_imbalance]
        D -- n_atoms > 500 --> R6[too_many_atoms]
        
        D -- Норма --> E[Расчет дескрипторов]
        E --> F[Определение магнитности]
        
        F --> G{Сравнение}
        G -- Совпадение с принятыми --> R7[duplicate]
        G -- Совпадение с train_set --> H[Флаг: is_novel = False]
    end

    %% Выходные артефакты
    subgraph Output ["3. Результаты и Отчеты"]
        G -- Прошел все тесты --> OK[validated_structures/]
        R1 & R2 & R3 & R4 & R5 & R6 & R7 --> RJ[rejected_structures/]
        RJ --> RJ_JSON[*.reason.json]
        
        OK & RJ --> CSV[all_structures.csv]
        CSV --> JSON[validation_report.json]
    end

    %% Стилизация
    style Pipeline fill:#f9f9f9,stroke:#333,stroke-width:2px
    style OK fill:#d4edda,stroke:#28a745
    style RJ fill:#f8d7da,stroke:#dc3545
    style S fill:#fff3cd,stroke:#ffc107
```
